# Этапы и состояние

## Этап 1. Репозиторий и сайт — сделан

pnpm-монорепо, сайт на Astro с островами на Svelte, CI в GitHub Actions, публикация на Vercel.

## Этап 2. База в Supabase — сделан

Таблицы `users`, `projects`, `docs`, `links`, `comments`, `bugs`; RLS на всех; права на столбцы; лимит частоты для комментариев и репортов; профиль создаётся триггером при регистрации. Всё записано в `db/schema.sql`, начальные данные — в `db/seed.sql`.

Проверено: `db/tests/rls.sql` — 65 проверок прав — проходит на живой базе и на локальной копии.

## Этап 3. Аккаунты, комментарии, баг-репорты, админка на сайте — сделан

Многостраничный сайт: главная, каталог, проект, баг-репорты, вход, регистрация, аккаунт, админка, состояние. Каталог и документация читаются из базы.

Проверено сквозным сценарием в браузере на локальной копии базы с настоящими RLS-политиками: 49 проверок (гость, регистрация, комментарии, лимит частоты, репорты, смена имени и пароля, админка, модерация, выход и вход, страница состояния, узкий экран).

Не проверено: работа на живом Supabase из настоящего браузера и приход письма с подтверждением. Это делает владелец после публикации.

## Этап 4. ПК-приложение — интерфейс сделан, оболочка ждёт первой сборки

Папка `app`: окно на Tauri 2 с теми же экранами и той же базой.

Проверено сквозным сценарием в браузере: 33 проверки, включая вход в приложении под аккаунтом, созданным на сайте, и появление комментария из приложения на сайте.

Оболочка на Rust в песочнице агента не собирается; её собирает GitHub Actions на `windows-latest`. Состояние сборки смотри в последнем запуске CI.
